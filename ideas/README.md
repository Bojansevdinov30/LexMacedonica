# Идеи — работи што НЕ се вклучени во апликацијата

Ништо од `app/` не увезува од овде, ништо не е инсталирано, ништо не се симнува
при import. Ова е тетратка со алтернативи: подготвени се да се пробаат, но
живиот пајплајн засега останува каков што е.

## 1. Реранкер (cross-encoder) пред LLM-от

Идејата: наместо RRF да одлучи кои 3 пасуси ги чита моделот, тоа го прави
**cross-encoder** — модел што го чита прашањето и пасусот ЗАЕДНО и дава многу
попрецизен скор од cosine меѓу два одделно вградени вектори. Прескап е за цел
корпус, па се пушта само врз кандидатите од евтиното пребарување.

**Двете верзии се вистински drop-in замени за `app/rag/retriever.py`**: имаат
ист потпис `retrieve(question, query_vector=None) -> RetrievalResult` и го
ре-извезуваат `embed_query`, па се вклучуваат со менување на ЕДНА линија.

| датотека | пајплајн | што бара да се смени | препорака |
|---|---|---|---|
| `retriever_reranked.py` | summaries → RRF → **реранкер** | ништо друго | ✅ почни од тука |
| `retriever_rerank_only.py` | RRF → **реранкер** (без summaries) | нов праг „Не знам" + послаба веројатност | експеримент |
| `reranker_model.py` | вчитување/скорирање на моделот | — | го делат двете |
| `reranker_benchmark.py` | мери латенција, разлики и праг | — | пушти го ПРВО |

### Како се вклучува

```bash
pip install sentence-transformers      # ~2.5 GB torch; моделот ~2.3 GB при прв повик
python -m ideas.reranker_benchmark     # прво измери на ТВОЈАТА машина
```

Потоа една линија во `app/rag/chains.py` (и по желја `app/lawyer/rag.py`):

```python
# from app.rag.retriever import embed_query, retrieve
from ideas.retriever_reranked import embed_query, retrieve
```

и испразни го семантичкиот кеш, инаку старите одговори го кријат ефектот:

```bash
python -c "import app.config; from app.vectorstore import _client; _client().delete_collection('semantic_cache')"
```

Враќање назад = врати ја старата линија (+ прагот, ако си пробал варијанта А).

### Зошто сè уште не е вклучено

- Моделот е ~2.3 GB + PyTorch ~2.5 GB инсталација.
- На CPU (без графичка) секој кандидат е едно поминување низ моделот, па
  латенцијата расте линеарно: проценка 3–10 s за 10 пасуси, трипати за 30.
  За жива презентација тоа е предолго — затоа постои benchmark скриптата.
- Тековниот двофазен пристап е со $0 дополнителна латенција и веќе дава
  добри резултати на корпус од 581 случај.

### Варијанта А бара уште два чекора

1. **Нов праг „Не знам"** — нејзиниот `max_similarity` е rerank-скор, а живиот
   праг 0.43 е измерен на summary-сличности. Измери го со
   `python -m ideas.reranker_benchmark --gate`, па постави го без менување код:
   `set LEX_MIN_SIMILARITY_FOR_ANSWER=0.xx`
2. **Свесност дека веројатноста е послаба** — `cases` таму се изведува од
   пасусите (помал и пристрасен примерок), наместо од ситуациска сличност.
   Деталите се во докстрингот на `retriever_rerank_only.py`.

## 2. Логирање на интеракциите — `interaction_logging.py`

Локална алтернатива на LangSmith: еден JSONL ред по прашање (прашање, дали е
кеширано/гејтирано, веројатност, цитирани случаи, токени, време). Покажува
точно кои три места во `app/rag/chains.py` би се смениле. Нула нови зависности.
`.env` веќе има `LANGSMITH_*` клучеви — ако сакаш хостирана верзија наместо
локална, доволно е `LANGSMITH_TRACING=true`, без ниту една линија код.
